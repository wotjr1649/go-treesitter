# Migrating from the removed `treesitter.New` / `syntax` API

The previous carrier API (`treesitter.New()`, package `syntax`, `internal/gtsadapter`) was removed with ADR-0022. It
remains in Git history at `9ad82eb` (`git show 9ad82eb:syntax/parser.go`). There is no compatibility package. This
page maps the names; the contracts are [`docs/specs/parser-result.md`](docs/specs/parser-result.md) and
[`docs/design/api-v2.md`](docs/design/api-v2.md).

| Removed (`9ad82eb`) | v2 |
|---|---|
| `treesitter.New()` → `syntax.Parser` | `treesitter.NewParser(lang, opts...)` → `*Parser`; call `Close` when done |
| `Request.Language` / `Request.Filename` (name or path detection) | a grammar module's `Language()`, e.g. `golang.Language()`; no detection by name or path |
| `Parser.Parse(ctx, Request)` → `Result` | `Parse(ctx, src, old)` → `*Tree` for incremental work, or `ParseSnapshot(ctx, src)` → `*Snapshot`; `ParseOwned` skips the source copy |
| `Request.Source` | the `src []byte` argument |
| `Request.Previous` + `Request.Edit` (byte offsets; points derived) | `Tree.Edit(InputEdit)` on the old tree, then `Parse(ctx, src, old)`; `EditFor(old, new, start, oldEnd, newEnd)` derives the points |
| `Request.Timeout` | a `ctx` deadline |
| `Limits.MaxInputBytes`, `MaxSnapshotNodes` | `WithMaxInputBytes`, `WithMaxSnapshotNodes` |
| `Limits.MemoryBudgetBytes` | `WithMaxMemoryBytes` (limits the instance's linear memory; not the same measure) |
| `Limits.IterationLimit`, `NodeLimit`, `StackDepthLimit` | none |
| `Result.Complete()` | `err == nil` (every accepted tree is checked: root end == input length) |
| `Result.Outcome` values `AcceptedClean`, `AcceptedWithErrors` | `Tree.Outcome()`; same names, now a `uint8` type. `Node.HasError()` on the root gives the same fact |
| `Timeout`, `Cancelled`, `ResourceLimit` | `*ParseError` with that `Outcome`; `errors.Is` with `ErrTimeout` (also `context.DeadlineExceeded`), `ErrCancelled` (also `context.Canceled`), `ErrResourceLimit` |
| `InvariantViolation` | `EngineFault` / `ErrEngineFault` |
| `UnsupportedInput`, `NotRun` | `InvalidInput` / `ErrInvalidInput` (nil ctx, bad option, non-UTF-8 with `WithStrictUTF8`, foreign `old`); `IncompatibleLanguage` is new |
| `EarlyStop` | none: a stopped parse returns an error and no tree |
| `Result.Diagnostics` (route, limits, token counts, arena bytes, …) | not provided; `Tree.InputBytes()`, `Tree.HasInvalidUTF8()`, `Snapshot.Len()` remain |
| `Result.Tree.Nodes()` → `[]syntax.Node` (`Type`, `Field`, `Parent` index, flags, byte/point spans) | `*Snapshot`: `Root()`, `Node(i)`, `All()`, `Walk`; `Node.Kind()`, `Field()`, `Parent()`, `IsNamed/IsExtra/IsMissing/IsError()`, `StartByte/EndByte/StartPoint/EndPoint()`; `Node.Index()` is the preorder index (the old slice was preorder too; v2 numbering is the engine's visible-node order, not guaranteed equal to the old one) |
| `Result.Tree.Close()` | `Tree.Close()` for a `*Tree`; a `*Snapshot` needs none |
| `syntax.NewIndex(nodes) (*Index, error)` | `treesitter.NewIndex(snap) *Index` or `snap.Index()` (cached) |
| `Index.OfType(t)` → `iter.Seq[int]`; `NodeAt(off)` → `(int, bool)` | `Index.OfType(kind)` → `iter.Seq[Node]`; `NodeAt(off)` → `(Node, bool)`; new `OfSymbol` |

## What behaves differently

1. **Outcomes are not a field.** A nil error means a complete tree, possibly with `ERROR`/`MISSING` nodes. Anything else is
   a `*ParseError` and no tree, so there is no partial result to inspect; the old `Result` returned diagnostics even on
   failure.
2. **Lifetimes and confinement.** The old parser owned a runtime parser per `Parse` call. A v2 `Parser` owns one engine
   instance, and the parser and its `Tree`s form one confinement unit: one goroutine at a time (misuse is reported as
   `InvalidInput`). `Close`, `Reset` and `ParserPool.Put` invalidate the parser's trees (`ErrTreeInvalidated`).
   `Snapshot` and `Node` are immutable and goroutine-safe, and outlive the parser. Use `NewParserPool` for concurrency.
3. **Editing is in place.** `Tree.Edit` leaves the tree usable only as `old` for the next `Parse`; `Snapshot` on it returns
   `ErrTreeEdited`, so take snapshots first. Incremental results are not guaranteed to equal a fresh parse.
4. **The snapshot owns its source.** `Parse` and `ParseSnapshot` copy `src` once; `ParseOwned` does not, and the caller must
   never modify the bytes afterwards. `Node.Text()` is a substring of that source. `Node` is a handle (snapshot pointer +
   index): the zero `Node` is the null node (`IsZero()`); every other method returns its zero value on it instead of panicking.
5. **Grammars are modules.** The root module has no grammar. Each language is its own Go module under `grammars/`,
   generated by `tools/gen`. v0.4.0 contains `bash`, `c`, `cpp`, `csharp`, `css`, `dart`, `golang`, `html`, `java`,
   `javascript`, `json`, `kotlin`, `php`, `powershell`, `python`, `r`, `ruby`, `rust`, `tsql`, `tsx`, `typescript`,
   `xml`, and `yaml`. [The README](README.md#use) lists sources and tiers; [limitations](docs/reports/limitations.md)
   records their measured scope. Between releases, development modules resolve through a local `replace` in their `go.mod`.

## Upgrading from v0.3.0 to v0.4.0 (engine ABI 3)

The exported Go API signatures are unchanged. Field lookup has these behaviour changes:

- **ERROR nodes:** `ChildByFieldName` and `ChildrenByFieldName` return nothing, as C's single-child lookup does.
  Upgrading the root applies this rule even to older grammar modules. `Node.Field()` still reports cursor metadata.
- **Alias-inherited fields:** with ABI 3 grammar modules (v0.4.0), `ChildByFieldName` can return a descendant inside a
  visible alias rather than a direct child. `ChildrenByFieldName` yields that result first, then other matching direct
  children without duplicates; an explicit null result yields nothing. Only its first result has a C counterpart.
- **Older modules:** the root accepts ABI 1, 2 and 3. ABI 1/2 modules have no field-exception table and retain
  direct-child lookup for alias-inherited fields; upgrade the grammar as well as the root to change this behaviour.
  ABI 1 (v0.1.0) still parses but `NewQuery` returns `ErrQueryUnsupported`; ABI 2/3 support queries.

A v0.4.0 grammar module requires root v0.4.0. PHP, PowerShell and Dart also move to new upstream revisions;
node-type schema changes are recorded in the [schema register](docs/validation/grammar-schemas.md).
See the [field contract](docs/specs/parser-result.md#field-lookup-and-grammar-compatibility) for exact semantics.

## Upgrading from v0.4.0 to v0.5.0 (engine ABI 3)

The exported Go API signatures and engine ABI stay unchanged. Upgrade the root and each grammar module you use:
a v0.5.0 grammar module requires root v0.5.0. Release module versions are prepared in the order specified by the
[publication procedure](docs/specs/publication.md#multi-module-release); development modules keep their local replacements.

- **PostgreSQL:** add `github.com/wotjr1649/go-treesitter/grammars/postgres` explicitly to use PostgreSQL SQL.
  PL/pgSQL is excluded. This owner-designated grammar has no named fields; inspect node kinds and children.
  There are now 24 grammar modules; Swift is outside this release.
- **Bash/Ruby heredocs:** the recorded scanner patches allow non-ASCII delimiters to close by comparing their
  stored low byte, with exact ASCII comparisons. Distinct non-ASCII code points with the same low byte still
  match, and delimiters whose low byte is zero still never close. Consumers may observe different trees for
  these non-ASCII heredocs; this is not full Unicode delimiter support.
- **YAML/Python scanner safety:** YAML `0002` and Python `0001` bound serialized indentation by bytes written,
  preventing scanner state-buffer overruns on deeply nested inputs (for Python, with an odd number of open
  string delimiters). Beyond the bound, indentation state is dropped and parsing can yield a full-length error
  tree instead of crashing; this does not add support for unlimited nesting. YAML's separate early-EOF patch
  from v0.4.0 is retained. All four new patches are disclosed under
  [ADR-0023](docs/design/decisions/ADR-0023-temporary-upstream-grammar-patches.md).
- **C source:** the module path remains `grammars/c`; its source moves from `tree-sitter/tree-sitter-c@b780e47`
  to the maintained fork `tree-sitter-grammars/tree-sitter-c@f3202ac`. The static node-type schema is unchanged;
  source and archive identities change. See the [v0.5.0 schema record](docs/validation/grammar-schemas.md#v050-preparation).
- **Snapshot memory and points:** snapshot arrays now use 25 bytes per node instead of 41, plus the owned source,
  sparse field exceptions and caches. Point access builds a shared lazy line index costing
  `4 * (LF count + 1)` bytes plus overhead, then uses O(log lines) lookups. An LF-only input can therefore add
  about four times its source size as line starts. Points follow source bytes; an `InputEdit` whose supplied
  points disagree with its byte offsets can now produce different points from native C. Use `EditFor` or
  supply consistent byte/point coordinates. `WithMaxMemoryBytes` still limits only instance wasm linear memory,
  not Go-heap snapshot arrays or indexes. See the [snapshot contract](docs/design/api-v2.md#6-snapshot-and-node).
- **Known grammar gaps remain:** T-SQL's pin stays unchanged; tested non-ASCII identifiers containing Hangul
  produce errors. C# EOF preprocessor directives need a final newline, and conditionals splitting a construct
  can produce errors. The [known-gap register](docs/README.md#contract-plane) records other input-specific C#,
  Python and T-SQL defects; upgrading does not fix them. Input must be UTF-8; transcode legacy encodings first.

[SECURITY.md](SECURITY.md) now describes private vulnerability reporting. The conformance corpus also gains a
bounded grammar-kit input subset; it is additional test coverage, not a new parsing feature or a language-validity
claim. See [limitations](docs/reports/limitations.md) for patch bounds and identity-bound evidence.

## Unreleased (after v0.5.0)

- **Public symbol IDs (#77, engine ABI 4).** Upgrade the root and the grammar modules you use. With the newer
  grammars, `SymbolForName(name, named)` returns the same kind of ID as `Node.Symbol()` and `Index.OfSymbol`.
  Refresh cached IDs from the active grammar using the original name and namedness. Rebuild caches that store
  only numeric IDs. Previous releases could return a raw ID that had no matching nodes for an aliased kind.
  Use `Index.OfType(name)` for every node with that name, including kinds with multiple public IDs. ABI 1–3 grammar modules still
  load with the new root and retain their raw ID lookup.

- **Ruby non-ASCII global variables.** Forms such as `$한글 = 1` now parse as assignments. A regular global name
  whose ASCII start (`$_`, `$a`, …) is directly followed by non-ASCII characters is now one `global_variable`
  spanning the whole name including `$`, wherever it appears. Such input used to parse without errors in two ways.
  In code (`$a한 = 1`, `x = $a한`, `puts $a한`, `$a한.foo`, `$a한 += 1`, `defined?($a한)`), the tree had a `call`
  whose `method` was `$a`, with the non-ASCII rest as an `identifier`, assignment or call in its arguments. In short
  interpolation (`"#$a한"`, also in heredocs and regular expressions), the `interpolation` covered only `$a` and the
  rest was `string_content` (`heredoc_content` in heredocs). Queries matching `(call method: (global_variable))`, the
  nested nodes or that string content lose those matches; `(global_variable) @global` captures the full name.
  [Schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-ruby-global-variable-patch)

- **Go 1.26 `new(expr)`** accepts `new(42)` with an `int_literal` under `argument_list` in place of an
  error. The Go parser also assigns new numeric IDs to some existing symbols. For example, the public
  `argument_list` symbol moves from 174 to 175. Use `SymbolForName` with the updated Go grammar (ABI 4) to refresh
  cached symbol IDs, and recompute cached subtree hashes after upgrading. The node-type names and named fields are the same.
  [Schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-go-new-expression-patch)

- **JavaScript v4.4.0:** `grammars/javascript` keeps the same Go API and moves from the patched owner
  v1.0.0 pin to v4.4.0 (`e5ada307a6f1741a573d5c8d4dafee9234330b1f`). Regenerate tree snapshots and
  rebuild cached numeric symbol IDs. The owner releases correct CSTs for `using` with a line break or
  a subscript, labelled statement blocks, `await` operands, default exports, automatic semicolon
  insertion, Annex B comments, and JSX quoted attributes. In queries, check immediate `await_expression`
  children, `export_statement.value` and following `empty_statement` siblings, comment ranges and
  attachment, and captures of JSX `string_fragment` and `html_character_reference`. The release also
  accepts hyphenated first segments in JSX member tags and parenthesized decorators. It rejects some
  inputs formerly accepted by v1.0.0, including `yield` expressions outside generators and JSX
  attributes with empty expressions. The owner grammar carries the JSX bare-ampersand fix.
  [Schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-javascript-v440) ·
  [Upstream changelog](https://github.com/wotjr1649/tree-sitter-javascript/blob/v4.4.0/CHANGELOG.md)

- **Rust block comments:** the scanner compares full Unicode code points when recognizing block comment
  delimiters and documentation markers. The unpatched scanner read a code point whose low byte is `/`, `*`
  or `!` (for example `是`, `갯`, `个`, `갪`, `Ī`, `😪`, `ġ`) as that ASCII character. Previously error-free
  trees can change when this low-byte misreading is corrected.
  - False documentation markers disappear. Ordinary comments such as `/*ġ foo */`, `/*Ī foo */` and
    `/*😪 foo */` retain their `block_comment` node and lose the spurious `inner` or `outer` marker field and
    `doc` child. Queries for `(block_comment)` still match these comments. Queries for their documentation
    children, including the upstream `@comment.documentation` highlight, stop matching them.
  - With a false nested opening removed, the comment ends at the `*/` that closes every opening the scanner
    counts. The rest is parsed as code: `/* 是个 */ */`, `/* a/Ī b */ */` and `/* a/갪 b */ */` now end with an `ERROR`
    over the stray outer `*/`, and `/*갯*//*/ */` is now two `block_comment` nodes. The scanner still does not
    count a `/*` that directly follows `/` (for example `//*`), an unchanged upstream limitation; where a false
    opening used to offset it, valid Rust such as `/* 是个 //* */ */` followed by code was error-free before and
    now ends the comment at the first `*/` with an `ERROR` over the second.
  - Removing a false nested closing or recognizing a previously hidden real `/*` can extend the block
    comment to a later real `*/`. With `fn f() {}` on the next line, both `/* /* 个是 */ // */` and
    `/* /* 个是 */ let x = 1; // */` still parse without errors. The block comment absorbs the separate
    `line_comment` and, in the second case, the `let_declaration`. In the upstream highlights query, the
    block comment's `@comment` range grows, the separate line comment's `@comment` disappears, and every
    capture inside the absorbed code disappears (here `@keyword` for `let`, `@constant.builtin` for `1` and
    `@punctuation.delimiter` for `;`). When real closes run out, `/* /* 个是 */`, `/* /* a*갯 */` and `/* 갯/* x */` end with a
    `MISSING` `*/`. With code after such a comment (`/* /* a*갯 */` followed by `fn f() {}` on the next line)
    the whole input is now one `ERROR`, and neither the `block_comment` nor the following item appears.
  - In a genuine documentation comment the `doc_comment` range can change: in `/**갪갯 */` it now also covers
    the space before `*/`.

  ASCII `/*!` and `/**` documentation markers and the static node-type schema are preserved. On Windows amd64,
  the decision 4 comparison used 195 fixed inputs (151 pinned upstream corpus cases, 16 fuzz seeds and edits,
  21 retained regressions, and 7 Korean corpus cases). A separate native enumeration covered 16,441 short
  comment inputs. See the [schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-rust-javascript-and-html-patches)
  for the input scope and results. Other inputs can change in the same ways.
  [Upstream issue #315](https://github.com/tree-sitter/tree-sitter-rust/issues/315)

- **YAML documents past 32,767 line breaks:** the scanner counts rows in 32 bits. It counts CR and LF
  separately, so row 32,768 is line 32,769 with LF (or CR) line ends and line 16,385 with CRLF line ends.
  Block mappings at or past that row no longer produce `ERROR` nodes from the row overflow. Some explicit
  keys (`? a`) whose `:` is at or past that row previously parsed without errors as a `block_mapping_pair` whose key held a nested
  `block_mapping`; they now parse as one `block_mapping_pair` with `flow_node` key and value. Queries on such
  keys and values see the new shape; node types, fields and the static node-type schema are unchanged.
  [Upstream issue #49](https://github.com/tree-sitter-grammars/tree-sitter-yaml/issues/49)

- **T-SQL v2.1.0:** `grammars/tsql` moves to the owner's `wotjr1649/tree-sitter-mssql`
  at `80037156b044543a8248299205a90552687c0c40`, with CLI 0.27.2 and no grammar patches.
  The Go signatures and engine ABI are unchanged. The schema diff's seven `CHILDREN_TYPE_REMOVED`
  entries describe existing nodes gaining named fields: function/procedure bodies move to `body`,
  the CTE identifier to `name`, and trigger object references to `name`/`target`.
  These fields were already present in alfpricot v1.0.0 (`852cbd20d7dc`); the nodes remain children,
  child traversal is unchanged by this field assignment, and `ChildByFieldName` now finds them.
  For this schema change, only consumers relying on the node-types `children` list must change:
  inspect `fields` as well. This is not a node removal or a general traversal/query compatibility break.
  Other additions and intended syntax rejections in v2.1.0 can still change parse results. Input that SQL Server
  rejects and the old grammar accepted now yields an error tree, for example `SELECT 1 WHERE;`, a variable as an
  alias (`SELECT 1 AS @a;`), `BACKUP ... WITH ENCRYPTION;` without options, an unterminated `/*` comment, and
  sqlcmd commands run into their argument (`:rfile.sql`). Review the
  [schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-t-sql-v210).
  The recorded Hangul alias, variable, column and label cases now parse cleanly and remain Korean regression inputs.
  This development change does not choose a module release version or authorize publication.

- **PostgreSQL Korean support (development tree after v0.5.0):** unquoted identifiers now accept every
  non-ASCII code point, including Hangul, NFD combining characters and supplementary characters, matching
  PostgreSQL's high-bit-byte lexical rule for UTF-8. ASCII identifier rules are unchanged. Adjacent names
  such as `SELECT값` remain one identifier instead of a keyword plus an invalid suffix. Dollar-quote tags
  compare full code points: `$끝$…$끝$` closes and `$걁$…$A$` does not. Existing trees containing these inputs
  can change. The grammar's `\s+` extras skip only ASCII whitespace. U+3000 and other non-ASCII spaces
  outside the original identifier range were lexing errors before and are identifier characters now, not SQL
  separators. The upstream 63-code-point dollar-tag cap remains, unlike
  PostgreSQL's unbounded dollar tags. PL/pgSQL and other upstream SQL grammar limits remain outside scope.
  These two temporary patches are an owner-approved 2026-11-17 Korean-support exception to ADR-0023
  decision 1, not a release-gate repair. See [upstream issue #101](https://github.com/gmr/tree-sitter-postgres/issues/101) and the
  [patch record](tools/gen/patches/postgres/README.md).
  The existing grammar can still accept `SELECT 9값;` as an integer plus alias, and
  `SELECT $9끝$body$9끝$;` as a parameter plus alias; the analogous ASCII inputs were already accepted.
  PostgreSQL rejects such adjacent numeric/parameter junk. A clean tree does not validate SQL against a server.

- **Bash/Ruby heredocs:** the recorded scanner patches now store end words as UTF-8 and compare full
  encoded characters. Korean end words no longer alias their ASCII low byte or another syllable with the
  same low byte. ASCII end-word bytes are unchanged. Invalid UTF-8 lookaheads compare as the same `0xFF`
  sentinel, distinct from U+FFFD; invalid input is not validated by this comparison. The shared 1024-byte
  scanner state buffer includes all open end words and metadata. Overflow returns zero serialized bytes
  and loses state, so roughly 330 Hangul syllables in total can exhaust it; other scanner state lowers
  the bound. This change does not remove other upstream heredoc syntax limits.
  Published v0.5.0 retains the earlier low-byte patch; these changes apply to the development tree.
  Bash `<<-` still strips `iswspace` characters, including U+3000, rather than tabs only.
  Different invalid bytes with the same number of decode errors can match. Stored words with different
  error counts differ, but Ruby repeated-word scanning can still close on a longer line.
  Ruby also closes on repeated end words such as `EOFEOF`; ordinary `EOFX` remains body text.
- **Bash heredoc closing lines:** after the UTF-8 storage change, the Bash scanner now requires the
  matched end word to be followed immediately by LF, CRLF or EOF.
  A prefix such as `EOFX` for `EOF`, `끝났다` for `끝`, trailing text, or `INNER)` stays in the body.
  Leading spaces and tabs before the end word are still ignored for every heredoc, including plain
  `<<EOF`: ` EOF` and `\tEOF` close it, although Bash keeps those lines in the body. This upstream
  limitation is unchanged; the new rule applies only after the end word.
  Consumers can observe different trees, including errors for scripts that used `INNER)` as a
  terminator instead of putting `INNER` and `)` on separate lines. This does not promise full
  logical-line continuation handling. Bash's `<<-` whitespace rule, invalid-byte aliases and
  scanner serialization limit remain; Ruby's repeated-word limitation is unchanged.

  In CRLF inputs the `heredoc_end` span now includes the CR byte; an end word followed by CR and EOF
  is also accepted. End-boundary state shares the existing serialized `started` byte, preserving the
  previous end-word capacity.

Query regex predicates change their default meaning without changing Go signatures or the engine ABI.
`#match?` and `#not-match?` use Unicode `\w`, `\d`, `\s` and `\b`/`\B`, and Unicode simple case folding for `(?i)`,
from the Unicode 16.0.0 tables in tree-sitter CLI 0.27.2's pinned `regex-syntax` 0.8.11. For example, `\w` now includes
Hangul, `\d` includes full-width digits, `\s` includes U+3000, and word boundaries recognize Hangul. The root module
still uses only the Go standard library. `#any-match?` and `#any-not-match?` validate the same regex syntax but remain
non-filtering properties, as in CLI 0.27.2.

To retain ASCII shorthand and word-boundary behavior, scope those constructs with `(?-u:...)`, for example
`(?-u:\w+\b)`. This escape hatch covers ASCII shorthand classes and boundaries; consuming classes are accepted
only when their final computed set is ASCII. Thus `(?-u:[^\W_])` works, while `(?-u:\W)`, `(?-u:\D)`, `(?-u:\S)`
and `(?-u:[^a])` are rejected. Its `\s` preserves Go's old ASCII set without vertical tab; CLI 0.27.2's ASCII `\s`
includes vertical tab, a recorded residual difference. `(?-u:.)`, non-ASCII byte matching and `(?i-u)` are rejected.
Invalid UTF-8 bytes cannot be consumed in Unicode mode; a literal U+FFFD still matches its valid UTF-8 encoding.

Patterns previously accepted by Go may now return a query error. Replace `\Qtext\E` with individually escaped
punctuation, octal `\101` with `\x{41}`, and `\0` with `\x{0}`. ASCII punctuation escapes such as `\_`, `\%` and `\!`
remain accepted. Rust constructs outside the supported subset also return a query error rather than silently changing
meaning: `\<`, `\>`, `\b{...}`, class set operations
(`&&`, `--`, `~~`, including `[--a]`, `[&&]` and `[a--]`), nested classes other than POSIX classes, verbose `(?x)`
and CRLF `(?R)` modes, Rust-only Unicode properties, repetitions above 1000 and dotted capture-group names. `\p{...}` supports Go categories and scripts and follows the consumer's
Go toolchain Unicode version; it can therefore differ from the pinned Unicode 16 tables. See the
[query contract](docs/design/query-abi.md#regex-predicate-subset-development-tree-after-v050) for the exact boundary.
Compilation budgets differ too: the CLI can reject Unicode repetitions such as `\w{1000}` for compiled size while
this implementation accepts them within its count limit.

Additional CLI-accepted forms outside this subset are nested repetitions (`a**`, `a*+`, `a{2}{3}`, `a*??`,
`a+?+`, `a{2}??`), whitespace inside repetition counts (`a{ 1 }`, `a{1 ,2}`), hex escapes longer than eight digits
(`\x{000000041}`), and nesting of 100 or more groups (the CLI allows up to 250). Normalize repetitions and hex
escapes and remove redundant groups. Byte classes such as `(?-u:[\x00-\xFF])` and byte folding enabled through
separate flag groups (`(?-u)(?i)a`, `(?i)(?-u)a`) are also rejected. Group names containing dots, brackets or
non-ASCII characters (`(?<n[1]>a)`, `(?<é>a)`) must be renamed to ASCII identifiers.

Unicode property names must match Go category/script names exactly. Rust's aliases, case-insensitive and loose
names (`Letter`, `lu`, `LU`, `Latn`, `Zyyy`, `han`, `Hira`, `gc=Lu`, `Math`, `Any`, `ASCII`, `Assigned`, ` L `)
are rejected; use exact Go names such as `L`, `Lu`, `Latin`, `Common`, `Han` or `Hiragana` where applicable.
Conversely, Go's surrogate category `\p{Cs}` and `\P{Cs}` are accepted as empty/all-scalar sets, whereas the CLI
rejects them. Unknown or case-variant POSIX-like forms (`[[:unknown:]]`, `[[:Alpha:]]`, `[[::]]`) that the CLI
interprets as nested classes remain unsupported. The [recorded CLI fixture](testdata/query-regex-cli.json) retains
these acceptance differences.

The following additions and one behaviour change affect the root module; the engine ABI is unchanged.

- **CP949 input:** `NewSourceCP949(raw)` decodes CP949 (the WHATWG `EUC-KR` index = windows-949; not IBM-949) with a
  built-in table, and `Encoding` has a new value `CP949`. `NewSource` still detects only UTF-16 BOMs: it never guesses
  CP949. See the [Korean and CP949 input guide](docs/guides/korean-input.md).
- **`Source.Replacements()`** counts the U+FFFD a conversion wrote (CP949 invalid bytes, unpaired UTF-16 surrogates; 0 for
  UTF-8). `WithStrictUTF8` and `HasInvalidUTF8` cannot see them, because U+FFFD is valid UTF-8.
- **`Source.UTF8Offset(orig int) uint32`** maps an original offset to an offset in `Bytes()`, the inverse of
  `OriginalOffset`.
- **`LineIndex.Offset(line, col, kind)`** maps a line and column (`ByteColumn`, `UTF16Column`, `RuneColumn`) back to a byte
  offset, clamping the way LSP does.
- **Changed: `LineIndex.Pos` inside a character.** For an offset in the middle of a multi-byte character, `UTF16Col` and
  `RuneCol` are now those of the character's start; before, each byte of the character was counted as a character, so the
  columns were not monotonic in the offset. `ByteCol` is unchanged. Offsets at character boundaries, and every node
  start and end of a valid UTF-8 source, give the same result as before.

### Java grammar v3.0.3

`github.com/wotjr1649/go-treesitter/grammars/java` uses owner grammar
[v3.0.3](https://github.com/wotjr1649/tree-sitter-java/tree/v3.0.3), commit
`358048c1c6f9f84335ca4a42141fd0798e6a36f2`. The Go import path stays the same.

- **Service providers (K17).** In `provides S with A, B;`, both `A` and `B` carry the required,
  repeatable `provider` field. Query with `(provides_module_directive provider: (_) @provider)`.
  The first field lookup now returns `A`. Update tree walkers that read the first implementation as
  an unfielded child.
- **Query-visible trees.** A `default` in a switch label list is an anonymous token (K3).
  Qualified record patterns such as `case T.R() ->` now match `record_pattern` and lose their
  call captures (K4). The upstream highlights capture the type. A qualified generic `super` call
  in a constructor body can now be an `explicit_constructor_invocation` (K2).
  These changes affect captures and kind-based dispatch even when the query still compiles.
- **Patterns, references and expressions.** Empty record patterns in lists and guarded labels are
  `record_pattern` nodes (K11, K26). A qualified `TypeName.super::m` has a named `super` child (K20).
  Postfix updates attach inside casts and unary expressions (K21), switch arrows delimit whole lambda
  results (K22), and `yield (n) + k` forms a `yield_statement` (K27). Contextual type names can now
  form `class_literal` nodes (K9, K29). Annotations on receiver parameters are represented within
  `receiver_parameter` (K7).
- **Literal and comment spans.** Encoded backslashes and text-block continuations change the
  bounds and placement of `escape_sequence` and fragment nodes (K10, K18, K19). An encoded
  backslash can leave a literal unterminated. An ordinary string with a raw backslash followed by
  a line terminator can now contain an error. Line comments end before CR, LF or CRLF (K23).
- **Reserved words and casts.** Phase 5 rejects Java's reserved words and literal spellings in
  identifier positions previously accepted. Inputs that relied on those tolerances can contain `ERROR`
  or `MISSING` nodes. Contextual names still work subject to the upstream `when` limits (K25 and K32).
  For signed operands, K34 reads `(Name) + x` and `(Name) - x` as additive expressions and withdraws
  tolerances such as `(@A Integer) -k` and `(void) -k`.

The [upstream changelog](https://github.com/wotjr1649/tree-sitter-java/blob/358048c1c6f9f84335ca4a42141fd0798e6a36f2/CHANGELOG.md)
records the 2.x and 3.x grammar changes and retained cases. See the
[Java schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-java-v303)
for the static contract changes.

### TypeScript and TSX grammar v3.1.0

The `grammars/typescript` and `grammars/tsx` Go modules use the shared owner
[grammar release v3.1.0](https://github.com/wotjr1649/tree-sitter-typescript/releases/tag/v3.1.0),
commit `c37edc69610d304fb2a11005ca9c4e52ad1f4863`. Their Go import paths stay the same.
This move from v1.0.0 includes the CST changes in v2.0.0 and v3.0.0.

- **Resource declarations and reserved words.** Walk and query the new `using_declaration` node for
  `using` and `await using`. Its `kind` field exposes the keyword tokens and its children include
  `variable_declarator`. Some previously accepted reserved names in binding positions now produce
  errors. Both grammars disable Annex B HTML-like comments.
- **Type arguments and expression precedence.** Tagged templates and postfix calls can now bind type arguments
  where v1.0.0 read a comparison. In `await f() as T`, `as` wraps the `await_expression`. `await f<T>().x`
  places the member access under `await_expression`, and qualified types stay together after `as` and
  `satisfies`. Check captures for `await_expression`, `instantiation_expression`, `non_null_expression`,
  and `parenthesized_expression` against the updated child alternatives.
- **Line breaks and comment ranges.** Automatic semicolon insertion now accounts for more line terminators
  and line-breaking comments. Comments at the end of a body or declaration can attach at a different level,
  and a hashbang ends before its terminating CR. v3.1.0 repairs member declarations named `in` or
  `instanceof` and fresh and incremental parsing around these operators after `async` or `await`.
  A newline-starting array after an `as import('x').Y` or `satisfies import('x').Y` expression
  remains a [known gap](https://github.com/wotjr1649/tree-sitter-typescript/pull/31).
- **TSX text and quoted attributes.** Bare `&` in JSX text or a quoted attribute parses as text.
  A bare or incomplete reference can change the number or byte ranges of `string_fragment` nodes.
  `<this.C/>` now has a `this` member object and JSX keyword names can carry type arguments.

The repository's highlights, locals and tags query files retain their bytes. CST changes can alter
captures and byte spans. See the
[owner changelog](https://github.com/wotjr1649/tree-sitter-typescript/blob/c37edc69610d304fb2a11005ca9c4e52ad1f4863/CHANGELOG.md)
and the [schema register](docs/validation/grammar-schemas.md#unreleased-after-v050-typescript-and-tsx-v310).
