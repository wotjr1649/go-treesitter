# ADR-0024 — Grammar source tiers: one upstream per language

**Status:** Accepted by the owner · 2026-11-15; rule 6 added 2026-11-16 · refines ADR-0020 §4 (which grammars) and ADR-0023 (how defects
are carried). The runtime upstream is `tree-sitter/tree-sitter` only, unmodified.

## Context

Wave-2 pins were copied from tree-sitter-grammar-kit. One of them (Kotlin, `tree-sitter-grammars/tree-sitter-kotlin`)
turned out to be a repository the ecosystem does not use (last commit 2025-01; nvim-treesitter and Helix use
`fwcd/tree-sitter-kotlin`), and we were about to patch its defects. The project is not a collection of other
repositories' features: each language must have one clearly justified upstream, and our own fixes stay recorded
patches (ADR-0023) reported upstream.

Tree-sitter's documentation places grammars in two organisations, `tree-sitter` and `tree-sitter-grammars` (the
latter linked from the former as community-maintained). Other grammars live in individual repositories; editor
distributions such as nvim-treesitter pick one per language.

## Decision

1. **Tier 1 — core:** the language has a grammar in the `github.com/tree-sitter` organisation → use it.
2. **Tier 2 — tree-sitter-grammars:** no tier-1 grammar, a grammar in `github.com/tree-sitter-grammars` that is
   maintained (a commit within the last 12 months at pin time) and is the one nvim-treesitter uses → use it.
3. **Tier 3 — third party:** otherwise the repository nvim-treesitter uses for that language, maintained as in 2.
4. **Owner-designated:** a language the owner needs that has no tier 1-3 source; the owner names the repository and
   the reason here.
5. Exactly one repository per language; no mixing of grammars or features from several repositories. Every tier gets
   the same release gates. The tier is shown in the README grammar list, the module README and `limitations.md`.
   Defects are carried only under ADR-0023 and reported upstream. A tier is re-checked when a pin moves.

## Consequences

- Kotlin is re-evaluated on `fwcd/tree-sitter-kotlin` (gates, speed); the patch prepared for the kit's repository is
  not used. The upstream PR already posted there stays as a contribution.
- T-SQL's pinned commit is preserved as a v0.2.0 release asset; PostgreSQL's `parser.c` is generated by us (pinned
  CLI), per earlier decisions.
- tree-sitter-grammar-kit is being absorbed into this repository; its grammar choices do not carry over unless they
  match this ADR.

## Amendment (2026-11-16): rule 6, following a maintained fork

6. **Follow a maintained fork.** When nvim-treesitter's `parsers.lua` (main) moves a tier-1 language to a maintained
   fork, we follow it after measuring the move. A maintained fork is (a) in `tree-sitter-grammars` or another
   repository nvim-treesitter pins, (b) not archived, (c) committed to within 12 months, (d) under the same licence
   text. The language keeps tier 1 by origin and is shown as "tier 1 (maintained fork)". Rule 5 still holds.

   Tie-breakers: the repository with better measured behaviour on our gates wins; if behaviour is equal, prefer the
   one nvim-treesitter pins; if the fork lacks commits the original has (GitHub compare `behind_by > 0`), stay and
   re-check at the next pin move; fixes we find are reported where issues are enabled (the original if the fork has
   none). The weekly upstream watch reports a different repository as a warning, never a failure or automatic move.

   A move is one pull request with: new identity and hashes in `tools/gen/pins.json` (licence bytes compared);
   strict `schema check`/`schema diff` old→new; native tree diff old→new over both pins' corpora and the pinned
   large inputs (`pin-move.yml`, exact fetched/verified base/head). Missing/invalid evidence fails; any ok→error
   blocks unless the PR body explicitly names that input on a `PIN-MOVE-ALLOW-OK-TO-ERROR <input-id>` line,
   retained visibly in the report. Schema removal/narrowing risks and changed trees are reported for review;
   regenerated module and the usual gates (conformance including the new repository's queries,
   bench); updated README, module README, schema register and `limitations.md`; owner approval per pin.

   The automated evidence procedure, including added/removed grammars and runs without explicit refs, is in
   [publication.md](../../specs/publication.md#grammar-pin-move-evidence); local replay and exact input-ID syntax
   are in [tools/gen](../../../tools/gen/README.md#pin-move-ci-evidence). The workflow does not authorize a move.

   First application, C (P43, 2026-11-16): `tree-sitter/tree-sitter-c@b780e47` → `tree-sitter-grammars/tree-sitter-c@f3202ac`
   (fork of the original, 2 commits ahead, 0 behind). `grammar.js`, `node-types.json`, licence and test corpus are
   identical; `parser.c` differs only in a gcc pragma and the patch version because the fork regenerated it with
   CLI 0.27.2 (byte-identical to our regeneration); native trees over the corpus are identical; the product wasm
   differs by one byte. nvim-treesitter moved for its own queries and bindings, not for grammar defects.

## Amendment (2026-11-16): tier review of tier-1 sources without a commit in 12 months

The weekly upstream watch flagged eight tier-1 pins whose repositories had no commit in 12 months (last commit
dates as reported on 2026-11-15): css 2025-09-28; go, html, java, javascript, python 2025-09-15; typescript and tsx
2025-01-30. Review result (owner, 2026-11-16): no maintained fork exists for any of them under rule 6, and
nvim-treesitter still uses the same repositories, so each language stays on its tier-1 repository. Defects are
carried as temporary patches under ADR-0023 and reported upstream; we do not wait for upstream to move (ADR-0026).

An accepted watch warning is recorded with an expiry of six months and reported in a separate table, so that only
new warnings stay at the top of the watch report. When an acceptance expires, the warning returns as new and the
tier is reviewed again. The accepted warnings and their expiry dates are kept in the upstream-watch tool
(`tools/native-ref/upstreamwatch`).
