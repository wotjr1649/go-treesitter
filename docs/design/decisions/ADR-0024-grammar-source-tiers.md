# ADR-0024 — Grammar source tiers: one upstream per language

**Status:** Accepted by the owner · 2026-11-15 · refines ADR-0020 §4 (which grammars) and ADR-0023 (how defects
are carried). The runtime upstream is `tree-sitter/tree-sitter` only, unmodified.

## Context

Wave-2 pins were copied from tree-sitter-grammar-kit. One of them (Kotlin, `tree-sitter-grammars/tree-sitter-kotlin`)
turned out to be a repository the ecosystem does not use (last commit 2025-01; nvim-treesitter and Helix use
`fwcd/tree-sitter-kotlin`), and we were about to patch its defects. The project is not a collection of other
repositories' features: each language must have one clearly justified upstream, and our own fixes stay recorded
patches (ADR-0023) reported upstream.

Tree-sitter's documentation places grammars in two organisations, `tree-sitter` and `tree-sitter-grammars` (the
latter linked from the former as community-maintained). Other grammars live in individual repositories; editor
distributions such as nvim-treesitter pick one per language.

## Decision

1. **Tier 1 — core:** the language has a grammar in the `github.com/tree-sitter` organisation → use it.
2. **Tier 2 — tree-sitter-grammars:** no tier-1 grammar, a grammar in `github.com/tree-sitter-grammars` that is
   maintained (a commit within the last 12 months at pin time) and is the one nvim-treesitter uses → use it.
3. **Tier 3 — third party:** otherwise the repository nvim-treesitter uses for that language, maintained as in 2.
4. **Owner-designated:** a language the owner needs that has no tier 1-3 source; the owner names the repository and
   the reason here.
5. Exactly one repository per language; no mixing of grammars or features from several repositories. Every tier gets
   the same release gates. The tier is shown in the README grammar list, the module README and `limitations.md`.
   Defects are carried only under ADR-0023 and reported upstream. A tier is re-checked when a pin moves.

## Current assignment (checked 2026-11-15)

| Tier | Language → repository |
|---|---|
| 1 | bash, c, cpp, c-sharp, css, go, html, java, javascript (+jsx), json, php, python, ruby, rust, typescript/tsx → `tree-sitter/tree-sitter-<lang>` |
| 2 | yaml → `tree-sitter-grammars/tree-sitter-yaml`; xml → `tree-sitter-grammars/tree-sitter-xml` |
| 3 | kotlin → `fwcd/tree-sitter-kotlin` (replaces the kit's `tree-sitter-grammars/tree-sitter-kotlin`); powershell → `airbus-cert/tree-sitter-powershell`; r → `r-lib/tree-sitter-r`; dart → `UserNobody14/tree-sitter-dart`; swift → `alex-pinkus/tree-sitter-swift` |
| owner-designated | T-SQL → `meloncholera/tree-sitter-mssql` (released since v0.1.0; nvim-treesitter has no T-SQL grammar); PostgreSQL → `gmr/tree-sitter-postgres` (nvim-treesitter has none; generated from PostgreSQL's own grammar) |

## Consequences

- Kotlin is re-evaluated on `fwcd/tree-sitter-kotlin` (gates, speed); the patch prepared for the kit's repository is
  not used. The upstream PR already posted there stays as a contribution.
- T-SQL's pinned commit is preserved as a v0.2.0 release asset; PostgreSQL's `parser.c` is generated by us (pinned
  CLI), per earlier decisions.
- tree-sitter-grammar-kit is being absorbed into this repository; its grammar choices do not carry over unless they
  match this ADR.
