# ADR-0029 — Included ranges for multi-language documents

**Status:** Proposed (implementation deferred until after 1.0, owner decision 2026-11-25) · 2026-11-25

## Context

A document can contain regions that belong to different grammars. A caller can discover those regions with an outer tree, then parse selected ranges with an inner grammar while keeping byte offsets and points in the original document. The Markdown block/inline split is the motivating use case. HTML with embedded JavaScript and CSS provides an integration fixture using existing grammars. [Tree-sitter v0.27.2, Multi-language Documents](https://github.com/tree-sitter/tree-sitter/blob/3fb7be49145acfb07e33b61ed5689e2b6771b2e9/docs/src/using-parsers/3-advanced-parsing.md#multi-language-documents)

ADR-0021 requires a complete result, a root-end check, a reset after a halted parse, and immutable, source-owning snapshots. API v2 initially scoped out included ranges. ADR-0028 permits additive stable API and a compatible engine ABI in a root minor while requiring released ABI 1–4 grammar modules to keep building and loading. This proposal is based on repository commit `e5e4b2980e53e796f969455023a6994af62a6f5e` and its runtime pin, tree-sitter `v0.27.2` at `3fb7be49145acfb07e33b61ed5689e2b6771b2e9`.

## Decision

### 1. Parser configuration

```go
func WithIncludedRanges(ranges []Range) Option
func (p *Parser) SetIncludedRanges(ranges []Range) error
```

`WithIncludedRanges` sets the initial ranges for `NewParser` and each parser lent by `NewParserPool`. `SetIncludedRanges` replaces that parser's active list for subsequent calls to `Parse`, `ParseOwned`, and `ParseSnapshot`. Multiple constructor options apply in argument order. A nil or empty slice selects the whole document. To represent a document with no regions for a given language, skip that language's parse.

Both entry points take a defensive copy. An option captures a valid slice when `WithIncludedRanges` is called and reports configuration errors when the option is applied. Reject an oversized list before copying. The setter holds the parser's existing single-owner guard, reports `ErrParserClosed` or concurrent use through the existing error paths, and updates only Go configuration. A failed setter leaves the previous list active. Live trees and snapshots retain their original meaning. `Reset` and instance recreation preserve the active list. `ParserPool.Put` restores the constructor list under the same guard before another borrower can get the parser.

Reuse `Range` and `Point` as they are. For example, in `"prefix\n[1,2]\nsuffix"`, use `[7,12)` with points `{Row: 1, Column: 0}` and `{Row: 1, Column: 5}` to parse the JSON array. A node's byte and point endpoints can populate a `Range` directly. For arbitrary endpoints, `LineIndex.Pos` supplies `Line` and `ByteCol`. With `Source` conversion, use offsets and points in `Source.Bytes()` and map back to the original file at the application boundary.

### 2. Validation, limits, and outcomes

| When | Rule |
|---|---|
| Configure | Accept at most **4,096** ranges per parse. Each interval is half-open with `StartByte < EndByte <= hardMaxInput` (`math.MaxInt32`). Require source order and `previous.EndByte <= current.StartByte`. Keep adjacent ranges as separate entries because external scanners can observe range starts. Points must be nondecreasing within and between ranges, with row and column each at most the endpoint's byte offset. |
| Admit a source | After the existing context, input size, UTF-8 and `old` checks, require each endpoint within `[0, len(src)]` and require its exact LF-counted row and byte column. Reject an endpoint inside a valid multi-byte UTF-8 sequence, including a split leading BOM. Permissive UTF-8 mode still accepts malformed bytes. Validate sorted endpoints in one forward pass over the original bytes, with bounded UTF-8 lookaround, no source copy, and no per-line allocation. Check cancellation during this pass and before staging engine buffers. |
| Accept a tree | Whole-document calls retain `root.EndByte() == len(src)`. For a nonempty list, require `root.EndByte() == ranges[len(ranges)-1].EndByte`. The root may have leading padding or span gaps. An unexpected root end is `EngineFault` with instance replacement. The native differential tests below must establish the ranged EOF invariant, including recovery, before this contract ships. |

Range validation failures use `InvalidInput` / `ErrInvalidInput` with the failing list index where available. They occur before input-dependent engine work. Existing context/error precedence and input-independent housekeeping continue to apply. A nonempty list on ABI 1–4 returns `IncompatibleLanguage` / `ErrIncompatibleLanguage` from `NewParser`, `NewParserPool` or the setter. Validate list shape before reporting missing capability. An ABI 5 module missing its declared export fails parser construction as incompatible. For an admitted list, an unexpected C rejection is an `EngineFault`. A refused `memory.grow` during range staging, installation, parsing or cleanup takes the existing `ResourceLimit` path with instance replacement. Cancellation uses `Timeout` or `Cancelled` and leaves no suspended parse. A complete tree with syntactic errors still returns successfully with `AcceptedWithErrors`.

`WithMaxInputBytes`, `WithStrictUTF8`, `HasInvalidUTF8`, and `Tree.InputBytes` apply to the full source, including gaps. `WithMaxSnapshotNodes` counts the exported tree's nodes. `WithMaxMemoryBytes` covers wasm linear memory, including the range buffer and the C parser/tree copies. A full list costs 96 KiB per copy at 24 bytes per entry. Go-side configuration and the snapshot's source and arrays follow the existing Go-heap accounting. Benchmark fragmented lists before committing to the maximum because the pinned lexer searches the range array during seeks.

### 3. Incremental parsing and snapshots

Apply `Tree.Edit` with full-document coordinates for every source edit, including edits in gaps or before the first range. Recompute the current list from the new document, usually from the new outer tree, and install it before passing the inner tree as `old`. `EditFor` computes consistent points. The parser's configured ranges stay fixed until replaced. For a range-only update on byte-identical source, the unedited old tree may be reused. The old tree must be live and belong to this parser in either case. Support adding, removing or moving ranges and switching between explicit ranges and full-document mode. The pinned C runtime edits each tree's stored ranges in `ts_tree_edit` and compares them with the current lexer ranges before reusing old subtrees. An incremental result can differ from a fresh one. [Pinned `tree.c`](https://github.com/tree-sitter/tree-sitter/blob/3fb7be49145acfb07e33b61ed5689e2b6771b2e9/lib/src/tree.c) · [Pinned `parser.c`](https://github.com/tree-sitter/tree-sitter/blob/3fb7be49145acfb07e33b61ed5689e2b6771b2e9/lib/src/parser.c)

`new.ChangedRanges(old)` keeps the existing native comparison. C accounts for inclusion differences while comparing the trees and returns syntactic changes, which can be empty. Preserve the C byte intervals because a result can refer to a region that was just removed. Compute points from the new full source, including the existing EOF clamping for points beyond it. The configuration count cap applies to input lists. Changed-range results keep their existing block bounds checks. Keep native range lists on C trees for edit and comparison. Callers can retain the lists they supplied for their own region bookkeeping. [Pinned `get_changed_ranges.c`](https://github.com/tree-sitter/tree-sitter/blob/3fb7be49145acfb07e33b61ed5689e2b6771b2e9/lib/src/get_changed_ranges.c)

Snapshots retain the full source and original-document coordinates with the existing `Parse` / `ParseSnapshot` copy rules and `ParseOwned` transfer. Points, descendant lookups and capture offsets use those coordinates. `Node.Text`, `AppendText`, leaf text used for hashes and atoms, and text predicates still use the contiguous source substring. A spanning node can therefore include excluded bytes in its text, and a position in a gap can resolve to a spanning node. Each selected region still feeds a single grammar, with one resulting tree per parse. Callers choose region grouping, languages, and any later stitching of trees or query results.

### 4. Engine ABI and release compatibility

Add one wasm export, `tsg_parse_included(src, len, old, ranges, count) -> tree`, in the repository's C shim. The current export table has no way to pass ranges to `ts_parser_set_included_ranges`. Use ABI 5 with a secondary Go `engine.IncludedRangeModule` interface containing `Xtsg_parse_included` with five `int32` parameters and an `int32` result. The base `engine.Module`, `engine.QueryModule`, `engine.Grammar`, old exports, snapshot format 2 and metadata format 2 keep their existing shape. A parse without an explicit list continues to call `tsg_parse`, including on ABI 5. Add export and version checks to the generator and regenerate through `tools/gen` without moving the runtime, CLI or grammar source pins.

Stage the source and list in wasm memory with checked allocation sizes and current memory bounds. Use a 4-byte-aligned, fixed 24-byte little-endian record per range with `start_row`, `start_column`, `end_row`, `end_column`, `start_byte`, `end_byte` as `u32`. This matches v0.27.2 `TSRange` on wasm32. Assert the layout in the shim. After C copies the list using `ts_parser_set_included_ranges`, invoke the existing UTF-8 parse and progress callback. Restore the default ranges with `(NULL, 0)` and then reset so the lexer starts at byte zero on its next use. Do this on success and ordinary no-tree returns. The C tree copies its list before the parser is restored. A trap or memory refusal discards the instance. Host staging stays live through the shim call and is freed on healthy return paths. Validate capability on instance creation, and use the existing generation invalidation on faults. [Pinned C API](https://github.com/tree-sitter/tree-sitter/blob/3fb7be49145acfb07e33b61ed5689e2b6771b2e9/lib/include/tree_sitter/api.h#L243-L270) · [Pinned lexer](https://github.com/tree-sitter/tree-sitter/blob/3fb7be49145acfb07e33b61ed5689e2b6771b2e9/lib/src/lexer.c)

The root can add this capability in a 1.x minor. A root-only update preserves released grammar behavior. A grammar tag that enables ranged parsing needs an ABI 5 rebuild and a minimum root version declaring ABI 5 support. Publish that root before dependent grammar tags and record combinations under ADR-0028.

## Consequences

- Markdown block + `markdown_inline` can parse the inline regions of each block node, subtracting child spans where the upstream binding does. Reuse the inline parser with an updated list for each node. The outer block grammar can parse on its own. [Pinned Markdown binding v0.5.4](https://github.com/tree-sitter-grammars/tree-sitter-markdown/blob/v0.5.4/bindings/rust/parser.rs)
- Vue can use its outer tree to find script, style and interpolation regions for JavaScript/TypeScript and CSS. The inspected Vue source imports `tree-sitter-html` at generation time. Its source and regeneration path still need their own ADR-0024 review. HTML script/style parsing provides a use case before any new grammar adoption. Candidate adoption remains a separate owner decision. [Vue grammar](https://github.com/tree-sitter-grammars/tree-sitter-vue/blob/main/grammar.js) · [Vue package manifest](https://github.com/tree-sitter-grammars/tree-sitter-vue/blob/main/package.json)
- Each inner parse stages the full source in wasm. Retaining many `Parse` or `ParseSnapshot` results can also retain many full-source copies. Measure time and peak memory for many inline nodes in a large Markdown document. Document region grouping and cost in the usage guide.
- On acceptance, record the scoped root-end amendment to ADR-0021 decision 2. Update the parser-result contract, API inventory and stability policy, engine ABI, and compatibility tables once the relevant evidence is available.

## Validation plan

| Lane | Required cases |
|---|---|
| Root tests | Exercise all three parse entry points, nil/empty reset, ownership of option and setter slices, rejected setters, cap and cap+1, reversed/empty/overlapping/adjacent intervals, source and hard bounds, mismatched positions, CRLF, leading BOM, Hangul and supplementary characters, split and malformed UTF-8, full-source limits, error precedence, pool restoration, reset and recycling. Inject malformed ABI, unexpected root end, traps/refused growth at each new engine step, and cancellation followed by a whole-document parse and a different ranged parse. Check snapshot validity after close/reset and contiguous text across gaps, including text predicates. |
| Native differential | Extend `tools/native-ref` and `tools/conformance` to use a native parser configured by `ts_parser_set_included_ranges`, with the same input, ranges, edits, pins and character-class semantics. Start with JSON, HTML/CSS/JavaScript embedding and a scanner-sensitive grammar or fixture that observes range starts. Include prefix/suffix gaps, adjacent and disjoint spans, trailing whitespace, BOM-only and whitespace-only selected spans, missing tokens, and malformed text. Assert the last-range root end independently in C, then compare canonical trees, error flags, byte/point endpoints and predicate-free structural query captures. For incremental cases compare Go incremental with C incremental after edits inside a range, in a gap, across a boundary and before all ranges. Include range-only updates and transitions to/from whole-document mode. Compare `ChangedRanges` byte intervals and independently check the public Go point projection. Use a C fresh parse as the oracle for Go fresh, and retain any native fresh/incremental differences. |
| Generator and consumer checks | Exercise the existing generator drift and `engine-consumer-compat` paths, with actual released ABI 1–4 tags, an ABI 5 tag candidate and a mixed consumer under `CGO_ENABLED=0`. Check the existing full-document syntax/query contracts and `IncompatibleLanguage` when requesting explicit ranges with an older grammar. Measure full-document regression and ranged setup/parse/export time and memory at small and worst-case counts, including a fragmented Markdown workload before enabling that grammar. |

Record the root commit, grammar and runtime pins, flags and recipe, platform, input and range lists, and edit sequence with the native differential results. Apply `docs/specs/validation.md` to any claim. This draft records source inspection. The native and performance gates above remain pending.

## Open questions

1. Keep the proposed configuration plus setter, or make range selection a property of new per-call entry points? The setter fits repeated Markdown parses and requires pool restoration.
2. Does the native matrix support exact last-range EOF through recovery, and does 4,096 keep seek time within budget? Resolve both before specifying stable behavior.
3. Which same-pin grammar builds should first ship ABI 5, and when should Markdown block and inline modules enter their separate adoption review? Vue also needs a source-policy decision.
