# Architecture overview

Normative for module layout and layer boundaries. Decisions and their reasoning live in
`docs/design/decisions/`.

## Layers

```
   consumer  (a product; not in this repository)
        │  depends only on this repository's own types
        ▼
   treesitter          public API: Parser, Tree, Snapshot, Node, Outcome (ADR-0021)
        │              no upstream or engine types exposed
        ▼
   internal/engine     versioned engine ABI over a translated wasm module (docs/design/engine-abi.md)
        ▲
        │ imported only by `treesitter` and by generated grammar modules
   grammars/<name>     generated by tools/gen from unmodified tree-sitter C (ADR-0020)
        ▲
        │ compared against
   native C reference  ← same runtime release and grammar sources, built natively (docs/specs/oracle.md)
```

## Layout

```
AGENTS.md              always-loaded kernel
README.md              human entry point
.gitattributes         LF pinning for fixtures
go.mod                 root module: the treesitter package and internal/engine

*.go                   treesitter package (parser_v2.go, snapshot.go, node.go, pool.go, ...)
internal/engine/       engine ABI; the only importers are treesitter and generated grammar modules

grammars/<name>/       one generated Go module per entry in tools/gen/pins.json (currently 15); never hand-edited
tools/gen/             generator and its pins (pins.json); regenerates modules reproducibly
tools/conformance/     compares the public API with native C reference dumps (needs the local reference data)
tools/bench/           speed and memory measurements
tools/modulezip/       builds official module ZIPs; tools/lane/ records command receipts

testdata/              external fixtures and corpus inputs, LF-pinned, hashed in docs/validation/workloads.md
docs/                  contract plane (see docs/README.md)
artifacts/             evidence plane, append-only
.github/workflows/     product, race and license lane (windows.yml), cross-platform engine lane (engine.yml)
```

`tools/*` and `grammars/*` are separate Go modules. The `treesitter` package is the public import path; it is
not versioned as a stable release yet (ADR-0022: first release is a v0.1.0 preview).

## Boundary rules

1. **Single import point.** Only the `treesitter` package and generated grammar modules import `internal/engine`.
2. **No upstream types cross the boundary.** The API exposes this repository's own types.
3. **No semantics in this repository.** Names, scopes, overloads, types, imports, code graphs, and
   memory/persistence are downstream concerns. See `docs/specs/parser-result.md` § Scope boundary.
4. **No downstream policy in this repository.** We make "incomplete" unambiguous; we do not decide
   whether a consumer publishes, keeps the previous state, or marks it stale.
5. **CGO only in diagnostic and reference lanes.** The product path must build and run with
   `CGO_ENABLED=0`; the race lane and the native C reference lane are the only exceptions
   (`docs/specs/validation.md`).

## Chosen pattern, in one line

**An explicit outcome/result model over a versioned engine seam.** No backend registry, no plugin system.
The old carrier (`internal/runtime`, `syntax`, `internal/gtsadapter`, ADR-0004/0013) was removed by ADR-0022 and
remains in Git history.

## Distribution

The root module is tagged `vX.Y.Z`; each grammar module `require`s that exact root version and is tagged
`grammars/<dir>/vX.Y.Z` (ADR-0022). Each tag still needs the owner's separate authority.
