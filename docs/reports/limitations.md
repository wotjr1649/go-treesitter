# Preview limitations (v0.4.0)

What the preview does not do or has not shown. Gate results and their evidence levels are on the
[status board](release-critical-status.md); this page lists the edges of them. Nothing here is release-approved.

| 9 | **`HasInvalidUTF8` is Go's `utf8.Valid`, not a tree-sitter notion.** It reports `!utf8.Valid(src)`. | 10 | **The zero `Node` is a null node, not an error.** `Node{}` is C's null node (for example from `DescendantForByteRange` when `start > end`). | 12 | **A grammar scanner that loops forever cannot be cancelled.** Cancellation and deadlines are checked by the parser between steps; an external scanner runs inside one step. A scanner that never returns keeps `Parse` from returning even after the context expires (observed with an unreleased Kotlin grammar on `val x = 1\n@Foo`, now reported upstream). No released grammar is known to do this; the nightly lane is configured to fuzz every grammar. Run untrusted input in a process you can stop if this matters. | [ADR-0024](../design/decisions/ADR-0024-grammar-source-tiers.md), [tree-sitter-kotlin#27](https://github.com/tree-sitter-grammars/tree-sitter-kotlin/pull/27) |

| 15 | **YAML differs temporarily from upstream.** Its `src/parser.c` carries `0001-no-early-eof`: lex state 0 no longer accepts an end token before checking end of input, preventing truncated roots including silent NUL truncation. | 16 | **Bash and Ruby carry a temporary heredoc comparison patch.** The scanners keep a heredoc delimiter one byte per code point (the low byte) but compared it with the full lookahead, so a non-ASCII delimiter never closed its heredoc. The patch compares an ASCII delimiter byte exactly and a non-ASCII one by its stored low byte, the same on hosts where `char` is signed or unsigned. Known limit: two different non-ASCII code points with the same low byte (for example `é` and U+0AE9) still match each other, and a delimiter code point whose low byte is 0 (for example U+0100) still never closes. Source pins are unchanged; engine and native reference use the same recorded C-only patches. Native unpatched/patched comparison over the corpus plus retained fuzz seeds/edits (116 Bash, 307 Ruby) found no change, and neither did 616 heredocs with ASCII delimiters (`EOF`, `X`, `_`, quoted forms) whose body lines hold other code points with the same low bytes or invalid UTF-8. Of 20 earlier Bash/Ruby heredoc probe inputs, eight change as intended (four per language) and the rest are unchanged, and 120 further non-ASCII-delimiter inputs were compared; in all 760 probe inputs the patched native (signed `char`) and Go dumps agree, and a `-funsigned-char` native build of the patched C agrees with the signed one (E5, Windows amd64). | [Bash patch](../../tools/gen/patches/bash/0001-heredoc-lookahead-char.patch), [Bash #370](https://github.com/tree-sitter/tree-sitter-bash/issues/370), [Ruby patch](../../tools/gen/patches/ruby/0001-heredoc-lookahead-char.patch), [Ruby #305](https://github.com/tree-sitter/tree-sitter-ruby/issues/305), [ADR-0023](../design/decisions/ADR-0023-temporary-upstream-grammar-patches.md) |
| 17 | **YAML and Python carry temporary scanner serialization bounds patches.** YAML `0002` reserves four bytes per indentation entry (upstream PR #47); Python reserves two (PR #351). The upstream overflow trigger is deep YAML block nesting, or deep Python indentation together with an odd number of open string delimiters (for example one string literal of any kind: ordinary, bytes, f-string or triple-quoted; two nested literals do not trigger it). The recorded comparison used the existing YAML `0001` baseline against `0001`+`0002` on 159 corpus/fuzz inputs, and unpatched/patched Python on 137: all byte-identical. Across 16 YAML and 15 Python P38/P40 probes, nine/five formerly crashing native inputs now return trees; all patched native/Go dumps agree (E5, Windows amd64). Nesting beyond the new bound (probed: YAML past 252 levels, Python past 511) is not parsed cleanly: the indentation state is dropped and the full-length tree contains ERROR nodes instead of crashing. The YAML early-EOF patch remains separate. | [YAML patch](../../tools/gen/patches/yaml/0002-bound-serialized-indent-bytes.patch), [YAML #48 / PR #47](https://github.com/tree-sitter-grammars/tree-sitter-yaml/issues/48), [Python patch](../../tools/gen/patches/python/0001-bound-serialized-indent-bytes.patch), [Python #350 / PR #351](https://github.com/tree-sitter/tree-sitter-python/issues/350), [ADR-0023](../design/decisions/ADR-0023-temporary-upstream-grammar-patches.md) |

## Release source mirror scope

The v0.4.0 release mirrors 24 source archives (22 distinct grammar archives, tree-sitter runtime and wasi-libc)
plus `SHA256SUMS`. Toolchain archives (wasi-sdk, binaryen and tree-sitter CLI for Linux and Windows) are fetched
from their official releases with pinned SHA-256 checks. This release provides no toolchain mirror fallback;
upstream tool availability remains a prerequisite until a complete bundled-notice inventory permits mirroring.
See the [2026-11-15 ADR-0026 amendment](../design/decisions/ADR-0026-never-block-on-upstream.md#amendment-2026-11-15)
and [source-row publication procedure](../specs/publication.md#pinned-archive-release-assets).
