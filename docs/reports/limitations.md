# v0.1.0 preview limitations

What the v0.1.0 preview does not do or has not shown. Gate results and their evidence levels are on the
[status board](release-critical-status.md); this page lists the edges of them. Nothing here is release-approved.

| # | Limitation | Evidence |
|---|---|---|
| 1 | **Wave-1 grammars only:** C#, T-SQL, TypeScript, TSX, Python, Go, JSON. Wave-2 grammars come after v0.1.0; the other languages of the removed carrier are not available. | [status board scope](release-critical-status.md#scope), [`MIGRATING.md`](../../MIGRATING.md) |
| 2 | **C agreement holds only on the listed inputs:** the session corpus (1,586 inputs), the grammars' own `test/corpus` (943 inputs, 2,829 seeded edits) and the seeded edit cases, compared with a native C build of the same pinned sources. It is not a guarantee for other inputs. | [status board gates](release-critical-status.md#wave-1-gates-session-15-windows-amd64-working-tree-grammar-modules-generated-by-toolsgen), [`oracle.md`](../specs/oracle.md), [`tools/conformance`](../../tools/conformance) |
| 3 | **Incremental may differ from fresh where native C does.** Five T-SQL edit cases differ in native C v0.27.2 and in the engine alike; they are ratcheted, not fixed. | [`known-regressions.md`](../validation/known-regressions.md#status-after-adr-0022), `knownIncrementalDiffs` in [`edits_test.go`](../../tools/conformance/edits_test.go) |
| 4 | **`Match` is experimental.** Accuracy was measured as 100 % on large single-token edits and 77-97 % matched (0.1-0.3 % wrong) on small edits, and it is weak when the edit produces ERROR recovery. It may change or be removed. | [`api-v2.md` §7](../design/api-v2.md#7-primitives-that-set-this-library-apart-v001), doc comment in [`match.go`](../../match.go) |
| 5 | **No queries yet.** The v0.1 signatures are fixed in api-v2 §8 but not implemented; neither are live per-node navigation, included ranges or legacy encodings. | [`api-v2.md` §8-9](../design/api-v2.md#8-queries-v01-signatures-fixed-now) |
| 6 | **Hardware faults are not recoverable.** A generated-code trap becomes a `*ParseError` (`EngineFault` or `ResourceLimit`) and the instance is recreated; a hardware fault on unmapped memory is not a Go panic and cannot be captured. The memory provider keeps every reachable address committed or bounds-checked. | [`Call` in `internal/engine/memory.go`](../../internal/engine/memory.go), [`engine-abi.md`](../design/engine-abi.md) |
| 7 | **Speed and memory were measured on Windows amd64 only** (large-input geomean 1.356x native, limit 2.5x; memory peak and release 72/72). Other platforms ran the test suites, not the benchmarks; Linux and macOS measurements follow v0.1.0. C-reference conformance ran in CI on Linux x64/arm64 and Windows x64 for the corpus-derived inputs only. | [status board gates](release-critical-status.md#wave-1-gates-session-15-windows-amd64-working-tree-grammar-modules-generated-by-toolsgen), [open items](release-critical-status.md#open-items-before-the-v010-preview) |
| 8 | **The balancing-cancel proof is on a probe build for two grammars.** Cancelling during tree balancing, then reparsing, was shown on a test-only probe build for JSON and TypeScript (494 of 682 stops landed in balancing; 682/682 next parses equal native C; 6/6 fail without the reset). Other grammars are covered by the general cancel-then-reparse test, not by that probe. The probe is not part of this repository. | [status board row](release-critical-status.md#wave-1-gates-session-15-windows-amd64-working-tree-grammar-modules-generated-by-toolsgen), [`TestCancelThenReparse`](../../tools/conformance/cancel_test.go) |
| 9 | **`HasInvalidUTF8` is Go's `utf8.Valid`, not a tree-sitter notion.** It reports `!utf8.Valid(src)`. Invalid bytes are parsed like C (decode errors in the tree); `WithStrictUTF8` rejects them instead. 189 invalid-UTF-8 inputs agree with native C. | [`parser-result.md` § Input](../specs/parser-result.md#input), [`utf8_test.go`](../../tools/conformance/utf8_test.go) |
| 10 | **The zero `Node` panics.** `Node{}` is C's null node (for example from `DescendantForByteRange` when `start > end`); only `IsZero` is safe on it. Check `IsZero` on any node that can be null. | doc comment in [`node.go`](../../node.go), [`parser-result.md`](../specs/parser-result.md#ownership-lifetime-concurrency) |

Release authority, tags and publication are separate from this list: see
[`publication.md`](../specs/publication.md).
