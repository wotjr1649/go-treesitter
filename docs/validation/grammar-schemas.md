# Grammar node-type schemas

Register of the static node-type schema (`node-types.json`) of every pinned grammar, as ADR-0020 decision 2 requires
with each grammar change. The file is read from the pinned upstream archive after its sha256 is verified against
`tools/gen/pins.json`; it is not hand-edited. A pin with `regenerate: true` additionally records the schema generated by the pinned CLI. A schema hash says nothing about parse
behaviour: equal schemas can still parse differently (for example after a precedence change).

## Offline strict-check inputs

The current candidate pin set contains 24 grammars, including the 2026-11-15 PHP, PowerShell and Dart revisions, the 2026-11-15
tree-identical T-SQL pin move and the C maintained-fork move below; `tools/gen/pins.json` SHA-256 is
`5467afce00a76529acf5dd13243a51d8218fa164c595ce171fc7fe6d78ea9913`. All 24 archived schemas pass the
strict check at this pin set (Windows amd64, Go 1.27.4).
The tables below record each schema once, grouped by the release that first recorded it; archive SHA-256
values identify the pinned upstream inputs. `tsx` and `typescript` share one archive. Schema bytes come from
`<grammarDir>/node-types.json` in that archive, after checking its digest, and match the generator's extracted input.

`TestPinnedSchemas` is an opt-in, offline strict format check; its invocation is documented in
[tools/gen](../../tools/gen/README.md#offline-node-type-schema-commands). Python's schema produces one
`REFERENCE_UNDECLARED` warning at `/9/fields/alias/types/0`: `as_pattern_target` (`named: true`) has no
separate node declaration. This warning can accompany `PASS`; it does not establish parse behaviour.

`postgres` regenerates `parser.c` and `node-types.json` without patches using the pinned CLI. Its candidate row below
records both the archived schema and the schema from the same independent generation run as the C parser;
these bytes match. YAML's ADR-0023 C-only patch
[`0001-no-early-eof.patch`](../../tools/gen/patches/yaml/0001-no-early-eof.patch) changes `parser.c`;
the upstream schema does not describe that patch's behavioural effect.

A new grammar's first entry is its baseline. When a pin moves, the entry records the old and new hashes and the
reviewed node-type diff from `go run . schema diff` in `tools/gen`
([ADR-0025](../design/decisions/ADR-0025-absorbing-tree-sitter-grammar-kit.md)), reviewed in the pin-change pull request.

## v0.4.0 candidate (nvim-treesitter pin refresh)

Based on main `dc3b23dc8813b8311e61a97051a6db77c1a287de`. The current nvim-treesitter
`main/lua/nvim-treesitter/parsers.lua` was read twice on 2026-11-15, including immediately before updating pins;
both reads selected the same revisions in the same repositories. Archives are codeload tarballs with SHA-256
recorded in `tools/gen/pins.json`; the previous baselines above are retained.

The 2026-11-15 schema tool is absent at this base, so these static node-type diffs use the existing manual review method:
records are keyed by `(type, named)` and their fields, child alternatives, subtypes and flags are compared.
The reviewed changes are:

- PHP: 305 records remain; `clone_expression.children.required` becomes false and an optional, single
  `arguments` field of type `arguments` is added.
- PowerShell: 322 → 323 records. The new named `background_operator` is allowed in the assignment `value`
  field and the children of `hash_entry` and `statement_list`. `command_elements` and
  `redirected_file_name` gain `unary_expression` child alternatives. `command_parameter` gains an empty
  `fields` object (a schema serialization change). No records are removed; six existing records change.
- Dart: 353 → 355 records, adding named `primary_constructor` and `primary_constructor_body_signature`.
  `class_definition` and `enum_declaration` gain optional `primary_constructor` fields and `const_builtin`
  children. The primary constructor body signature becomes a child alternative in `declaration` and
  `method_signature`. `constant_constructor_signature` replaces its `identifier` child alternative with an
  optional, multiple `name` field accepting `.`, `identifier`, and `new`; `constructor_signature.name`
  becomes optional. `enum_body.children`, `enum_declaration.body`, `extension_declaration.body`, and
  `extension_type_declaration.body` become optional. `enum_declaration` moves `type_parameters` from child
  alternatives to an optional single field. `representation_declaration` gains `final_builtin` children
  and optional single `parameters` of type `formal_parameter_list`, while its `name` and `type` fields
  become optional. No records are removed; ten existing records change.

These are static schema changes and do not establish parse behaviour. No license/notice bytes changed; large benchmark input
identities are independently pinned and unchanged.
